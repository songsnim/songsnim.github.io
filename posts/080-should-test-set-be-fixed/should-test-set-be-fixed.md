대학원에서 AI 관련 연구를 하다보면 오픈 데이터셋들을 고정해두고 학습과 테스트를 진행합니다. 이런 방식에 익숙해져 있는 상태에서 입사를 해 실제 **production 수준**에서 ML 제품을 개발하다보면 수집되는 데이터가 추가되면서 dataset이 지속적으로 변하는 `data drift`를 맞닥뜨리게 됩니다. 여기서 의문이 발생합니다.
> val이나 test set도 그에 맞게 변화해야 하는가?
> val이나 test set이 변하면 학습 간의 유의미한 성능 비교가 불가능한데?
> 그렇다고 해도 `data drift`를 무시할 수는 없는데?

이 글에서는 위 의문점들에 대해 나름의 답변을 해보겠습니다.

## 1. test set을 고정해야 하는가? 고정하면 안 되는가?
결론부터 말하면 **"둘 다 필요하다"** 입니다.
모델이나 기법 간 성능 비교가 목적인 경우에는 고정된 **golden set**을 사용하고,
요즘 수집되는 데이터에도 잘 동작하는지 확인하는 목적인 경우에는 고정되지 않은 **production set**을 사용해야합니다.
하나만 고르는 문제가 아니라, 목적에 따라 어떤 것으로 평가를 할 것인지 고르면 됩니다.

## 2. Golden Test Set
- 목적
새로운 모델링 기법, 아키텍쳐, 학습 알고리즘 성능을 공정하게 비교
- 특징
영상을 수집한다고 치면, 카메라 모델이 바뀌는 물리적인 문제가 아니고서는 절대 변경되지 않아야 합니다.
따라서, 처음 구축할 때 데이터의 품질과 대표성이 매우 중요합니다.
여기서 test set이 문제 해결 지표의 역할을 잘 수행할 수 있도록, 해당 도메인 전문가들의 수작업과 노가다, 아주 엄밀한 검수가 필요합니다.

## 3. Production Test Set
- 목적
`data drift` 발생 여부를 탐지하고, 현재 모델과 후보 모델이 요즘 데이터를 얼마나 잘 대표하는지 평가
- 특징
지속적으로 업데이트되는 데이터셋으로, 딱히 정답은 없고 ML 엔지니어의 문제 해결 방향에 따라 구축 방법이 달라질 수 있습니다.
최근 1주일, 최근 1달, 최근 1년 데이터만 사용할 수도 있고, 최초 수집 시점부터 누적된 전체 기간에서 test set을 선정해 구축할 수도 있습니다.
단, 지속적으로 발생하는 작업이므로 자동화가 가능한 방향으로 설계해야 합니다.

## 4. 결론
> val이나 test set도 그에 맞게 변화해야 하는가?
> val이나 test set이 변하면 학습 간의 유의미한 성능 비교가 불가능한데?
> 그렇다고 해도 `data drift`를 무시할 수는 없는데?

보통 ML을 공부할 때 고정된 dataset을 사용하기 때문에 이런 의문이 생기곤 합니다.
실제 ML 제품을 개발하는 경우에는 비즈니스 상황에 맞춰 평가 지표도 여러개일 수 있고, 평가 데이터도 당연히 여러개일 수 있기 때문에, 고정된 test set이 있을 수도, 계속 업데이트 되는 test set이 있을 수도 있습니다.
공정한 성능 평가를 위해서는 초기에 잘 정의된 **golden test set**을 사용하고, `data drift`를 고려하고 싶다면 지속적으로 업데이트 되는 **production test set**을 평가 test set으로 활용하면 됩니다.
